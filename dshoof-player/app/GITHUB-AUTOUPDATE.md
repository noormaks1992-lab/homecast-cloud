# تشغيل دشوف وتحديثه — الإصدار 3.3

المصادر القابلة للمراجعة في `app/`، واللقطة الكاملة في
`dshoof-player/source.snapshot.json`. يعيد `tools/release.mjs` توليد اللقطة
وبيان الفروق ونسخة مشغّل البداية المستقلة من هذه المصادر.

## التحديث من GitHub

يقرأ `github-start.mjs` عند بدء التشغيل فرع `noor-player-m3u` في المستودع الخاص
`noormaks1992-lab/homecast-cloud`، ومسار `dshoof-player/source.snapshot.json`.
تحديث فرع تطوير آخر لا يغيّر الإصدار الذي يجلبه. تعديل المشغّل داخل اللقطة
لا يحدّث المشغّل المثبت أصلًا في جذر الاستضافة.

أمر البدء لهذه الآلية هو `node --env-file-if-exists=.env github-start.mjs`.
المفتاح `DSHOOF_GITHUB_TOKEN` بصلاحية Contents: Read-only لهذا المستودع فقط،
ويُحفظ في إعدادات الاستضافة أو `.env` الخاص، دون رفعه إلى GitHub.
يظل `DATA_DIR` ثابتًا بمسار مطلق، وتبقى إعدادات المنفذ والاستضافة الحالية.

قبل تفعيل الآلية، افحص أمر البدء الحقيقي وGitHub autoPull في المنصة، واحفظ
نسخة خاصة من الشفرة والبيانات. التحديث وإعادة التشغيل يقطعان المشاهدة مؤقتًا.
لا تستخدم Restart بوصفه إثباتًا لنشر فرع غير الفرع المحدد.

## فحص الإقلاع والرجوع

- التنزيل محدود الحجم والمهلة عبر HTTPS، مع رفض التحويلات التي تحمل المفتاح.
- تُجهّز اللقطة في مجلد مستقل، وتُفحص صياغة JavaScript والاعتماديات أولًا.
- لا يُمرّر مفتاح GitHub إلى الخادم أو FFmpeg أو أوامر تثبيت الحزم.
- تحصل كل محاولة بدء على `DSHOOF_BOOT_ID` عشوائي جديد. يقبل المشغّل
  `/healthz` فقط عند تطابق `bootId` و`release` مع العملية الحية التي أنشأها؛
  استجابة خادم قديم على المنفذ لا تعتمد المرشح ولا تغيّر مؤشر الإصدار.
- لا يبدأ البديل إذا لم تنتهِ مجموعة عملية المرشح السابق. تنظيف مجموعة المشرف
  لا يثبت زوال مجموعة الخادم المستقلة عند انهيار المشرف نفسه؛ إيقاف خدمة
  Botkeep كاملة والتحقق من توقفها مطلوبان قبل رفع الملفات أو الرجوع اليدوي.
- الرجوع التلقائي بعد فشل الإقلاع يحتاج نسخة سابقة تدعم `bootId` و`release`.
  النسخ القديمة التي لا تدعم هذا العقد تُرفض. عند ترقية تثبيت قديم، احتفظ
  بالمشغّل والملفات الأصلية للرجوع اليدوي بعد إيقاف الخدمة كاملة، دون مسّ البيانات.
- عند تعذر GitHub يُختار الإصدار المخزن في `.dshoof-current.json` قبل ملفات
  الجذر؛ حذف المفتاح وحده أو رفع ملفات الجذر لا يعطّل اختيار الإصدار المخزن.
- صحة الإقلاع لا تثبت أن مزوّد الفيديو يعمل أو أن حصة CPU تكفي لكل المشاهدين.

## النشر بالملفات فقط

خطة هذه الصيانة في `../tools/DEPLOYMENT.md`: قراءة موثقة لهوية الخدمة وأمر
البدء وربط GitHub، ثم نسخة احتياطية خاصة، وإيقاف خدمة Botkeep كاملة، ورفع
الفروق المتحققة فقط، وفحص البصمات قبل التشغيل وبعده. يلزم `autoPull=false`
لهذا المسار المحدود. عند الحاجة يحل قالب `tools/pinned-start.mjs` محل المشغّل
المثبت بعد التحقق من الجذر و`DATA_DIR`، حتى لا يعيد لقطة قديمة فوق التحديث.

لا تُرفع `data/` أو `.env` أو `node_modules/` أو مجلدات الإصدارات المحفوظة.
حالة الإصدار وتجارب البث وحدود التحقق في `../UPGRADE-2026-10-18.md`، ونتائج
الاختبارات النهائية في `../release/validation.json`. ملفات الدليل وحدها ليست
إثباتًا لإتمام النشر على Botkeep.
