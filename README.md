# HomeCast Cloud

لوحة عربية خاصة لإدارة قناة IPTV من استضافة خارجية. يشغّل السيرفر الفيديو ويقدّم رابط M3U/HLS/TS ثابتًا. تشغيل رابط إنترنت أو فيديو مرفوع لا يحتاج بقاء الحاسبة المنزلية تعمل. إرسال شاشة الحاسبة يحتاجها أثناء الإرسال.

**هذه نسخة جاهزة للنشر، وليست إثباتًا على وجود استضافة مفعّلة.** لا يوجد عنوان استضافة حقيقي أو حساب GitHub مضمّن في الملفات. GitHub يحفظ المشروع؛ GitHub Pages وحده لا يشغّل FFmpeg أو سيرفر البث.

## ما الذي توفره؟

- صفحة دخول بمفتاح تحكم، جلسة HttpOnly/Secure، حماية CSRF وتحديد محاولات الدخول.
- تشغيل رابط فيديو مباشر، HLS/DASH أو صفحة يدعم استخراجها yt-dlp أو فاحص عناصر الفيديو والإطارات. لا تتجاوز تسجيل الدخول أو DRM.
- رفع فيديو حتى 512 ميغابايت وتشغيله في حلقة، مع صوت صامت للفيديو بلا مسار صوتي.
- قناة واحدة بجودة مختارة أو قائمة بالجودات 144/240/360/480/720/1080؛ التحويل يبدأ حسب المشاهدة.
- الحفاظ على إطارات المصدر افتراضيًا، أو خرج 60 إطارًا بالتكرار دون تسريع الفيديو.
- إعادة محاولة مصدر متوقف ومراقبة FFmpeg، ومنافذ المعالجة داخلية فقط.
- رابط مشاهدة بمفتاح منفصل عن مفتاح التحكم؛ لا تشارك مفتاح التحكم.

## تشغيل على سيرفر مستقل مع Docker

تحتاج Linux مع Docker Compose، اسم نطاق يشير إلى السيرفر، وفتح TCP 80/443 في جدار السيرفر. اسم نطاق فرعي توفره خدمة استضافة مناسب أيضًا إذا شغّلت الحاوية مباشرة مع HTTPS الذي توفره.

```sh
bash prepare.sh
docker compose up -d --build
docker compose logs --tail=50 homecast
```

افتح `https://YOUR_DOMAIN` وسجّل الدخول بالقيمة `CONTROL_TOKEN` الموجودة في `.env`. لا تغيّر `STREAM_KEY` أو النطاق إذا أردت استمرار روابط الرسيفر نفسها. `prepare.sh` يحافظ على `.env` الموجود ولا يولّد مفاتيح جديدة فوقه.

يخزّن Compose الإعدادات والفيديوهات في volume دائم باسم `media`. احفظ نسخة احتياطية من هذا volume ومن `.env`. لا تستخدم `docker compose down -v` إن أردت الاحتفاظ بالملفات. يبدأ السيرفر مع Docker بعد إعادة تشغيله باستخدام `restart: unless-stopped`، ويظل معتمدًا على توفر السيرفر والطاقة والشبكة والمصدر.

## تجربة مجانية على Render

ارفع المستودع إلى حسابك على GitHub، ثم من [Render](https://dashboard.render.com/) اختر **New → Blueprint** وحدّد المستودع. يتضمن `render.yaml` خطة **free** صراحة، ومفاتيح يولّدها Render، ومسار فحص `/healthz`. يقرأ التطبيق عنوانه العام من `RENDER_EXTERNAL_URL` تلقائيًا.

بعد اكتمال النشر افتح عنوان `onrender.com`، ومن إعدادات Environment انسخ `HOMECAST_CONTROL_TOKEN` للدخول. لا تضع المفاتيح في GitHub. لا تربط وسيلة دفع لتجربة تريد إبقاء تكلفتها صفرًا. يحوّل التطبيق مفتاح المشاهدة الذي يولّده Render بصيغة base64 إلى قيمة آمنة للرابط؛ انسخ مفتاح البث الفعلي من تفاصيل لوحة HomeCast عند ربط برنامج الحاسبة.

**خطة Render المجانية للتجربة فقط، ولا تحقق طلب بث قوي دائم:** تدخل السكون بعد 15 دقيقة بلا طلبات، ولها حدود ساعات/نقل ومعالجة؛ 0.1 CPU لا يكفي لضمان تحويل بث مباشر بهذه الجودات. تخزينها مؤقت، فتُفقد الإعدادات والفيديوهات المرفوعة عند إعادة إنشاء الخدمة. يمكن وضع `HOMECAST_INITIAL_URL` في متغيرات الاستضافة لاستعادة مصدر URL عند غياب الإعدادات المحفوظة. لا يوجد نظام طلبات وهمية لإلغاء حدود الخدمة.

المراجع: [خدمات Render المجانية](https://render.com/docs/free)، [مواصفات Blueprint](https://render.com/docs/blueprint-spec)، [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

## الاستخدام بعد النشر

1. ادخل إلى الموقع بمفتاح التحكم.
2. ضع الرابط واضغط **استخراج الفيديو وبدء البث**، أو اختر فيديو واضغط **رفع الفيديو وتشغيله**.
3. اختر **قناة واحدة** وجودة مناسبة، واترك الإطارات على **نفس المصدر** ثم احفظ.
4. نزّل **قائمة M3U** إلى الفلاش واستوردها في الرسيفر. جرّب **صيغة TS البديلة** إذا لم يدعم الرسيفر HLS أو HTTPS بالشكل المطلوب. بعض الرسيفرات القديمة تحتاج بوابة محلية إذا لم تدعم TLS؛ لا يمكن تأكيد توافق جهاز بعينه دون تجربته.
5. لتغيير المحتوى كرّر الخطوة 2. لا تحتاج تغيير رابط القناة عند تغيير المحتوى أو جودة القناة الواحدة.
6. استخدم **فحص وصول البث** للتحقق من القائمة والمقطع، ثم جرّب المشاهدة الفعلية على الرسيفر.

لربط برنامج HomeCast المحلي: افتح خيار الخارجي وأدخل عنوان الموقع ومفتاح التحكم ومفتاح البث الموجود في تفاصيل الموقع. عند استخدام قائمة السيرفر الخارجية مباشرة، تظل مشاهدة URL أو الفيديو المرفوع مستقلة عن الحاسبة. بث الشاشة يظل محتاجًا إلى حاسبة تعمل وترسل الصورة والصوت.

## إعدادات الاستضافة

| المتغير | المعنى |
|---|---|
| `PUBLIC_BASE` | عنوان HTTPS الكامل للموقع، بلا مسار. اختياري على Render. |
| `HOMECAST_CONTROL_TOKEN` | مفتاح عشوائي بطول 32 حرفًا أو أكثر؛ يولّد `prepare.sh` قيمة 64 hex. |
| `HOMECAST_STREAM_KEY` | مفتاح مشاهدة منفصل، 24 حرفًا أو أكثر. |
| `HOMECAST_ROOT` | مجلد بيانات قابل للكتابة؛ `/data` في Docker. يحتاج volume للاحتفاظ بالملفات. |
| `PORT` | منفذ الموقع العام، الافتراضي 8080. |
| `HOMECAST_INITIAL_URL` | مصدر URL ابتدائي عند عدم وجود إعدادات محفوظة. |

لتشغيله دون Docker: Node.js 22+ وFFmpeg/ffprobe وPython/yt-dlp، ثم اضبط المتغيرات وشغّل `npm start`. للـ Linux استخدم التثبيت داخل Docker للحصول على التبعيات معًا. `HOMECAST_FFMPEG` و`HOMECAST_FFPROBE` و`HOMECAST_YTDLP` تسمح بتحديد مسارات البرامج للاختبارات أو التثبيت المخصص. `HOMECAST_DEV=1` يسمح HTTP على loopback فقط للاختبارات ولا يُستخدم في النشر.

## التحقق

```sh
npm test
```

تختبر الاختبارات حدود الدخول، حماية CSRF، حظر الأصل المختلف، عزل المسارات الداخلية، صلاحية الجلسة ومفتاح المشاهدة. لا تختبر قدرة خطة الاستضافة أو ثبات الإنترنت. استهلاك الفيديو التقريبي لقناة واحدة 480p نحو 0.87 GB/ساعة (1.8 Mbps فيديو + 128 kbps صوت، دون احتساب الزيادة البروتوكولية)، أي نحو 625 GB لشهر 30 يومًا عند مشاهدة مستمرة. كل مشاهد إضافي يضيف نقل بيانات.

لا توجد استضافة أو منظومة تضمن عدم الانقطاع مطلقًا. حفظ اسم النطاق ومفتاح البث يحافظ على تركيب الرابط، واستمرار تشغيله يتطلب إبقاء الاستضافة والمصدر متاحين. لا تضع ملفات `.env` أو `config.json` أو مجلدات البيانات في المستودع.
